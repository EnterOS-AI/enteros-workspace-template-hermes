# Light runs: what a run's copy of this agent's volume leaves out (contract C2).
#
# A Light run pod's init container copies the parked agent's volume into the
# run's private directory with molecule-runtime-light-copy, which reads this
# file through MOLECULE_LIGHT_COPY_EXCLUDE_FILE (see the Dockerfile).
#
# One pattern per line, relative to the volume root: configs/... is /configs,
# and HERMES_HOME (/tmp/.hermes) links to /configs/.hermes (start.sh). A
# pattern is matched with fnmatch.fnmatchcase against the whole path, where *
# also matches /, so files are named in full rather than as *.log; a * only
# ever follows a fixed name (state.db*, .update_*), which keeps it in its own
# place. A trailing / matches a directory and everything under it. The runtime
# itself always leaves out configs/.auth_token, configs/.platform_inbound_secret
# and lost+found/.
#
# Everything else is copied: the agent's identity and config (SOUL.md,
# config.yaml, .env), credentials (auth.json, mcp-tokens/), skills, memories,
# plugins and the workspace's own files. tests/test_light_copy_exclude.py checks
# every line against a measured claim and runs a real copy.

# Conversation history: a run starts a fresh session.
configs/.hermes/state.db*
configs/.hermes/sessions/
configs/.hermes/response_store.db*
configs/.hermes/runs_idempotency.db*
configs/.hermes/.hermes_history
# Messages the gateway queued or spooled to disk (queued user messages, the
# overflow FIFO, transcript rows the in-memory cap dropped); its startup
# recovery would replay them into the run's fresh session store.
configs/.hermes/pending_messages/
# Copies of the session store: /snapshot and pre-update snapshots, and backups.
configs/.hermes/state-snapshots/
configs/.hermes/backups/
# Media people sent the agent or got from it, the citations ledger and
# tool-output spill. The rest of cache/ is rebuilt on use.
configs/.hermes/cache/

# Logs: hermes writes logs/, start.sh the two files. gateway-starts.log is the
# gateway's respawn-storm ledger: a run copied soon after five agent gateway
# starts would sleep 10-300 s before its own gateway came up.
configs/.hermes/logs/
configs/.hermes/gateway.log
configs/.hermes/molecule-mcp-server.log
configs/.hermes/gateway-starts.log

# The agent's own gateway and processes: PID, lock and state files that

# A pending restart or update notice: the run's gateway would announce a

configs/.hermes/.restart_notify.json
configs/.hermes/.restart_pending.json
configs/.hermes/.update_*

# Work the gateway starts by itself. Its cron ticker fires the due jobs in
# cron/, and its kanban dispatcher (kanban.dispatch_in_gateway, on by default)
# starts ready tasks and reclaims orphaned ones, so a copy would do the agent's
# scheduled and board work a second time. A run therefore sees neither the
# agent's hermes cron jobs nor its kanban board.
configs/.hermes/cron/
configs/.hermes/kanban.db*
configs/.hermes/kanban/
